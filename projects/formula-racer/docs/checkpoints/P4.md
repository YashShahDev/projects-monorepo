## P4-C1 — Blender car, export, anchors, LODs and validation

State: done. Requires P3 (`6331e67`).

**LFS transfer.** P0 had only proved the batch endpoint. `assets/probes/lfs-probe.png`
(165 B, oid `248b07a3d0…`) was committed as a pointer and pushed (`Uploading LFS objects:
100% (1/1)`). A fresh `--depth 1` clone of the branch with smudging off then ran
`git lfs fetch` and `git lfs checkout`, and the file matched the source SHA-256 as an
8×8 PNG. Only after that was the car GLB (1.7 MB) added under
`public/assets/**/*.glb` LFS tracking.

**Model interface** (`content/cars/model-interface.json`, parsed by
`src/content/car-model.ts`). The renderer and the Blender script both read it, so names
cannot drift:

| Node                                           | Role                                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------------ |
| `body`                                         | Holds `body_LOD0…2`; origin is the chassis collider centre                     |
| `wheel_FL`, `wheel_FR`, `wheel_RL`, `wheel_RR` | Hub pivots in physics wheel order; spin about local x; LOD children            |
| `wing_front_flap`, `wing_rear_flap`            | Hinge pivots at the flap leading edge, rotated about local x for Straight Mode |
| `camera_chase`, `camera_cockpit`               | Anchors: chase aim point above the engine cover and driver eye point           |
| `collision`                                    | Box matching `chassisHalfExtents` (±3 cm), no material; not drawn              |

Frame: game chassis frame (+z forward, +y up, driver's right −x), metres. Every
LOD node has `<name>_LOD0…2` mesh children, finest first.

**Validation** (`tools/validate-car-model.ts`) reports every problem in one pass:
missing or duplicated required nodes; stray meshes outside the interface; scaled
named nodes; missing LOD levels; LODs that do not shrink; per-level triangle budgets
(60k/16k/4k); wheel pivots within 1 cm of the physics hubs, wheel meshes centred with
the physics radius; overall size inside the 2026 envelope (length 4.8–5.4 m, width
1.8–1.9 m, height 0.9–1.0 m from the wheel bottoms), so a unit or scale mistake fails;
collision box against the physics box; a material on every visible primitive; texture
slots with no image or a type other than PNG/JPEG/KTX2; baked normal and AO maps on
the body; and unreadable files, such as a `.gltf` whose texture file is missing.

**Car** (`assets/blender/fr26_car.py`, Blender 4.5.14 background, factory settings).
The survival cell, sidepods and airbox are lofted through smoothed superellipse sections.
The front and rear wings are NACA-style airfoils, with a beam wing, endplates, a
swan-neck pylon, wishbones, a halo, mirrors and a helmet. The floor has a tapered
diffuser. Wheel pivots, tyre radius and the collision box come from `fr26.json`. The
body is UV-unwrapped. Procedural panel and noise bump are baked in Cycles CPU (seed 0,
64 samples) to a 1024² tangent-space normal map and a 1024² AO map, with a temporary
ground plane. The bump nodes are then stripped. Occlusion is exported through the
`glTF Material Output` group. Body LOD1 and LOD2 are decimated copies, 25% and 6%.
Wheels are lathed at 48/24/12 segments, and flaps are built at three airfoil
resolutions.

Result: LOD0 18,596 triangles (body 13,100, four wheels 960 each, two flaps 828
each), LOD1 5,442, LOD2 1,400; 5.22 m × 1.89 m × 0.95 m; GLB 1.7 MB. The export
takes about 20 s on this machine, and three consecutive exports were byte-identical
(`08d12895c422…`).

Commands: `make assets` rebuilds and validates. `make assets-verify` rebuilds into a
temporary folder and fails unless the result matches the committed GLB byte for byte;
it is part of `make test-full`. `make test` validates the committed GLB and fails with a
clear signal on an LFS pointer file.

Tests: 226 unit (18 new: interface parsing, every validation failure class on
in-memory fixtures, a missing texture file, and the shipped GLB); `make test` 17/17
browser; `make lint` passes. One `make test-full` run had five chromium-dev timeouts
(30 s, page closed) under load; an immediate rerun of the matrix passed 73/73. Per the
user, later checkpoints run the Chromium tests only.

Not done in C1: the renderer still draws the greybox box car. Loading the GLB, the
fixed-camera screenshot and the browser loading test belong with P4-C3 (cameras and
animated wings/wheels), which consumes this interface. KTX2 texture compression is
deferred until the rendering measurements the phase asks for.

## P4-C2 — Liveries, circuit and second map

State: done.

**Liveries** (`public/assets/cars/liveries.json`, `src/content/livery.ts`). The three
fictional schemes are Vermilion #8 (the greybox red), Tidewater #12 and Nightjar #23.
Each carries only an id, a name, a number, and `#rrggbb` paint and accent colours. The
parser rejects any other key ("liveries are visual only"), so performance stays equal by
construction. Lap keys do not include the livery.

- The choice lives in the pause menu, and changing it does not restart the lap.
- It is saved in `formula-racer:prefs` (`src/app/preferences.ts`). An unknown, corrupt or
  blocked saved value falls back to the first livery.
- The greybox body shows the paint colour.
- The model interface gains `liveryMaterials: ["paint", "accent"]`, which the validator
  requires on `body_LOD0`. The Blender car now has an `accent` material (endplates,
  mirrors) included in the bake.
- The re-export was reproducible (`79e41e3773e5`).
- Tests: 8 livery/preference unit tests, 1 validator test, and a browser test in which
  choosing Tidewater removes the red car pixels and survives a reload.

**Circuit.** Harbour Park, built in P2-C2 against this phase's layout requirements, is
the original circuit: 3.93 km, 12 m wide with 1.5 m kerbs, a 1.29 km active-aero back
straight, an R18 hairpin, a 90° R250 sweeper, a 35° chicane and medium corners, with at
least 25 m of run-off between non-adjacent parts. The existing `tests/track.test.ts`
suite ("the shipped circuit") already asserts each feature, the run-off clearance and
the start on the road, so it was reused rather than duplicated. The autopilot laps it
cleanly in about 111 s. Kerbs stay greybox vertex colours until the P4-C3 presentation
pass.

**Second map and loading.** `public/assets/tracks/tracks.json` catalogs the loadable
tracks (`src/content/track-catalog.ts`). Ids are limited to `a-z0-9-` because they
become file paths, ids must be unique, and a track file must carry the id the catalog
gives it. Test Loop (`test-loop`, 1.1 km, 49 control points) is generated from
`content/tracks/test-loop.layout.json` like Harbour Park, and the regeneration test now
covers every shipped layout. The app loads the first catalog entry, or the one named by
`?track=<id>`; an unknown id shows the startup alert listing the available ids. The
timing panel shows the track name.

Tests: 10 new catalog/Test Loop unit tests (parsing, unsafe and duplicate ids, default
and unknown choice, base-path fetch order, id mismatch, missing file, size, start on
road, run-off clearance) and 4 browser tests (default name, Test Loop renders road and
car, its own start distance drives the session, unknown id). `make lint` passes;
Chromium browser 22/22, the track tests 12/12 over `--repeat-each 3`.

Environment note (cloud session): 245/247 unit tests pass. The two shipped-GLB tests
fail only because Git LFS could not fetch `fr26.glb` here: the batch endpoint loops on
307 redirects since the repository rename (`claude-projects` → `projects-monorepo`).
They pass wherever LFS objects are present. Playwright ran against the preinstalled
Chromium through an untracked config.

Known issue: the dev server has no `/favicon.ico`, so the 404 can race into
`collectErrors` in any browser test that asserts no console errors.

- **Sound** (`src/audio/sound-model.ts`, `src/audio/car-audio.ts`). A pure model maps rpm,
  throttle, speed, lateral acceleration (speed × yaw rate) and the wheels on a kerb to:
  engine pitch at the V6 firing frequency (200–625 Hz) and gain; tyre squeal from 1.8 g,
  full at 4.5 g; kerb rumble at the 5 m stripe rate. Pausing silences all three. Web
  Audio plays it: a low-passed sawtooth plus a sub-octave, band-passed and chopped
  seeded noise. Audio starts on the first key or pointer press (autoplay rules), and a
  browser without Web Audio stays silent. The Sound checkbox mutes it and is saved.
- Wheels already spin and steer in the greybox renderer (P2).

Tests: 9 sound-model, 7 quality/preference and 2 sound-preference unit tests; browser
tests for the preset (resolution, road still drawn, remembered) and sound (engine gain and
pitch rise on throttle, mute remembered). `make lint` passes; 263 unit tests pass (the 2
shipped-GLB tests need LFS objects); Chromium browser 25/25 (`chromium-dev` only).
